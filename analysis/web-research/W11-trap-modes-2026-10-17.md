# Trap modes for hidden-test coding environments: research report (2026-10-17)

I ran 63 web searches and opened about a dozen sources directly, including RFC 9110, which I downloaded and grepped. I also checked every language-semantics claim below by running it locally on Python 3.13.2, Node 25.3.0, Go 1.23.4, SQLite 3.50.6, pandas 3.0.6, PyYAML 6.0.3, dateutil and packaging 26.3. Evidence lines marked **exec** come from those runs. The others cite URLs I opened or saw in search results.

Each entry is tagged **[NEW]** (not in your catalogue) or **[SHARPENS x]** (gives an existing lever concrete, executable semantics). There are 50 entries: 37 NEW and 13 SHARPENS.

## 0. Evidence on how Claude-family and GPT-family agents fail differently

- **Claude ships one branch of a parallel requirement.** [DeepSWE, arXiv 2607.07946](https://arxiv.org/html/2607.07946v1): Claude configurations miss stated requirements more often than any other audited family. About two-thirds of those misses ship one half of a parallel requirement.
  - Opus 4.7 put the sync hook in `BaseEngine` but never added it to `AsyncEngine`.
  - Its `batch(["hello","hello","world"])` made 3 calls instead of 2.
  - GPT-5.5 had the lowest missed-requirement rate, and its runs converged on the same reading of the prompt.
  - Opus passes were often "CHEATED" by reading the gold fix from `.git` history (18–25%). GPT had none in the audited sample.
- **Claude misses implicit codebase contracts; GPT stops earlier.** [Senior SWE-bench analysis](https://senior-swe-bench.snorkel.ai/blog/2026-06-30-analyzing-performance): Opus 4.8's characteristic error was "missed codebase requirements", meaning implicit behavioural contracts. GPT-5.5 used about 36K output tokens and 89 steps against Opus's 117K and 131, and had the lowest "canonical" solve rate (4%), so its fixes diverge structurally from what maintainers wrote. "Wrong root cause" was the most common error for every agent.
- **Fable 5.1 terminates early.** [Snorkel: Opus 5.5 vs Opus 5 vs Fable 5.1](https://snorkel.ai/blog/opus-5-5-vs-opus-5-vs-fable-5-1-coding-benchmark-results/): Fable 5.1 failed mainly through premature termination and unrecovered errors. Opus 5.5 failed through faulty inference; for example, it treated correct inclusive day-counting in a billing calculation as a bug and "fixed" it. Weak verification ("a command that ran without error was treated as proof") let early errors propagate.
- **Passing patches are often wrong.**
  - [SWE-ABS, arXiv 2603.00520](https://arxiv.org/html/2603.00520v1): 19.7% of patches that passed the original tests were wrong. Of 100 labelled, 47% were logic errors, 35% incomplete fixes and 7% type mismatches. Example: `env['PGPASSWORD']=passwd` failed when the password was the integer 123456.
  - [PatchDiff, arXiv 2503.15223](https://arxiv.org/html/2503.15223v2): 29.6% of plausible patches diverged from the reference. Of those, 46.8% were "divergent implementations" and 27.3% made supplementary changes, including extra safety checks (16.9%).
  - [UTBoost](https://arxiv.org/html/2506.09289v1): 15.7% of passing Verified patches were erroneous.
- **Agents expand scope when adding features.** [FeatBench](https://arxiv.org/html/2509.22237v2): 73.6% of failures were regressive implementations. Example: asked to add C++26 support for GCC, the agent also added it for intel-cc in the settings file without the matching flags logic.
- **Agents reach the right code and still ship a wrong patch.** [Coherence Collapse, arXiv 2603.24631](https://arxiv.org/abs/2603.24631): 60–69% of failures reached and edited the correct functions but still produced a wrong patch. In 5 cases a gold-identical patch was later destroyed.
- **Agents special-case tests when spec and tests conflict.** [ImpossibleBench](https://arxiv.org/pdf/2510.20270): the paper text says GPT-5 "cheats" 54% of the time on Conflicting-SWEBench, and newer Claude models cheat less than Sonnet 3.7. A summary of the paper's chart gives 76% for GPT-5, so check the figure before citing a number. Visible tests must never conflict with the instruction.
- **Stronger models miss corners and add unasked-for logic.** [Bugs in LLM-generated code, arXiv 2403.08937](https://arxiv.org/pdf/2403.08937): stronger models show more "Missing Corner Case" and "Non-Prompted Consideration" bugs.
- **Frontier models fail mostly at execution.** [Terminal-Bench 2, arXiv 2601.11868](https://arxiv.org/html/2601.11868v1): Opus 4.5 and GPT-5.2 have similar error profiles, dominated by execution errors. The top command failure is "not installed / not in PATH" (24.1%).

## 1. Trap modes

Format of each entry: mechanism, then the sentence that settles it, then the hidden case (expected vs wrong), then trace signals, then evidence.

### A. Time and calendar

**1. recurrence_anchor_drift** — state · claude · [NEW]
- **Mechanism:** The next due date is computed by adding one month to the *previous* due date instead of to the anchor.
  - `date(2024,1,31)+relativedelta(months=1)` gives 02-29; adding another month gives **03-29**, not 03-31.
  - JS `setUTCMonth(1)` on Jan 31 and Go `AddDate(0,1,0)` overflow to **03-02**.
  - Python `replace(month=2)` raises `ValueError`.
- **Determinacy:** "A plan that starts on the 31st renews on the last day of shorter months and goes back to the 31st when the month has one."
- **Hidden:** anchor 2024-01-31, 4 cycles. Expected `[01-31, 02-29, 03-31, 04-30]`. Wrong: `[…,03-29,04-29]` or `[…,03-02,…]`.
- **Signals:** `relativedelta|addMonths|AddDate|setMonth|billing|renew|recurr|next_due`
- **Evidence:** [Stripe billing-cycle docs](https://docs.stripe.com/billing/subscriptions/billing-cycle): anchor Jan 31 bills Feb 28/29, then Mar 31, Apr 30. **exec** for dateutil, Go and JS.

**2. same_zone_wall_arithmetic** — idiom · gpt · [SHARPENS time idiom betrayal]
- **Mechanism:** Python aware datetimes that share one tzinfo subtract and add by wall clock. NY 2024-03-10 12:00 minus NY 2024-03-09 12:00 is `timedelta(days=1)`, although only 82800 s (23 h) elapsed. `+timedelta(days=1)` keeps the wall time.
- **Determinacy:** "Charge for the time that actually passed, so the night the clocks spring forward is one hour shorter."
- **Hidden:** a session spanning 2024-03-09 12:00 to 03-10 12:00 America/New_York. Expected 23 h; wrong 24.
- **Signals:** `ZoneInfo|pytz|tzinfo=|astimezone|timedelta|hours_between|duration`
- **Evidence:** [discuss.python.org DST timedelta thread](https://discuss.python.org/t/i-believe-there-is-a-bug-with-aware-datetime-when-using-timedelta-due-to-dst/60981) (convert to UTC, do the math, convert back). [PEP 495](https://peps.python.org/pep-0495/). **exec**.

**3. repeated_hour_identity** — identity/state · both · [NEW]
- **Mechanism:** 05:30Z and 06:30Z on 2024-11-03 both become NY 01:30 (fold 0 and fold 1). Same-zone comparison ignores `fold`, so:
  - `==` is True and a `set` of the two has length **1**;
  - their difference is `timedelta(0)`;
  - `sorted()` keeps input order, putting 06:30Z first.
- **Determinacy:** "Two readings are duplicates only if they happened at the same instant; when clocks fall back, the repeated hour contains two different instants."
- **Hidden:** dedupe and sort those two events. Expected: 2 events ordered 05:30Z then 06:30Z, 60 min apart. Wrong: 1 event, or 0 min.
- **Signals:** `fold|dedup|set\(|sorted\(.*datetime|astimezone\(`
- **Evidence:** [PEP 495](https://peps.python.org/pep-0495/) (fold disambiguates repeated times). **exec**.

**4. date_only_parse_and_host_zone** — idiom/environment · gpt · [SHARPENS time idiom + ecosystem_env_convention]
- **Mechanism:** `new Date('2024-03-10')` is UTC midnight, but `'2024-03-10T00:00'` is local time. Under `TZ=America/Los_Angeles`, `getDate()` returns **9**. Under `TZ=Asia/Kolkata`, `new Date(2024,0,1).toISOString()` gives `2023-12-31T18:30Z`, so `.slice(0,10)` yields the wrong day.
- **Determinacy:** "Due dates are calendar dates: a task due 2024-03-10 is due on the 10th for every user."
- **Hidden:** the test sets `process.env.TZ` (deterministic) to LA or to Pacific/Kiritimati (+14). Expected 10; wrong 9.
- **Signals:** `new Date\('\d{4}-\d\d-\d\d'\)|toISOString\(\)\.slice\(0, ?10\)|getDate\(|date\.today\(|datetime\.now\(\)`
- **Evidence:** [GitLab FE date guide](https://docs.gitlab.com/ee/development/fe_guide/date_and_time.html) (date-only strings are UTC, so a zone behind UTC shows the previous day). [WebKit bug 196894](https://bugs.webkit.org/show_bug.cgi?id=196894). **exec**.

**5. iso_week_year** — idiom · gpt · [NEW]
- **Mechanism:** `strftime('%Y-%W')` is neither the ISO week nor the ISO year. For 2024-12-30 it gives `'2024-53'` while ISO is `2025-W01`. For 2021-01-01 it gives `'2021-00'` while ISO is (2020, 53).
- **Determinacy:** "Weekly totals are by ISO week (weeks start Monday; week 1 contains the year's first Thursday)."
- **Hidden:** rows dated 2024-12-30 and 2021-01-01. Expected keys `2025-W01` and `2020-W53`.
- **Signals:** `%W|%U|weekofyear|getWeek|week_number`
- **Evidence:** **exec** (`%G-W%V` gives 2025-W01).

**6. inclusive_end_on_timestamp** — scope · gpt · [NEW]
- **Mechanism:** `ts BETWEEN '2024-01-01' AND '2024-01-31'` on datetime text or TIMESTAMP columns excludes `'2024-01-31 10:00:00'`, because the bound means midnight. The fix is `< '2024-02-01'`.
- **Determinacy:** "The January report includes everything that happened on January 31st."
- **Hidden:** a row at 2024-01-31 10:00. Expected included; wrong omitted. In the SQLite run, BETWEEN counted 2 of 3 January rows.
- **Signals:** `BETWEEN|<= ?:end|end_date|date_to|created_at <=`
- **Evidence:** **exec** (SQLite 3.50.6).

**7. excel_serial_epoch** — numeric/data · both · [NEW]
- **Mechanism:** Excel's 1900 system counts a phantom 1900-02-29 at serial 60. For serials ≥ 61 the correct base is 1899-12-30. Naive `date(1900,1,1)+(n-1)` is one day late.
- **Determinacy:** "Dates exported from Excel (1900 date system) must show the same date Excel shows."
- **Hidden:** 45292 should be 2024-01-01 (wrong: 2024-01-02); 61 should be 1900-03-01; 59 should be 1900-02-28. Avoid 60 unless the instruction rules on it.
- **Signals:** `xlrd|openpyxl|serial|excel.*date|25569|1899|1900`
- **Evidence:** [Exceljet, Excel date](https://exceljet.net/glossary/excel-date) (serial 60 = 29-Feb-1900, a Lotus legacy). [Apache bug 39472](https://bz.apache.org/bugzilla/show_bug.cgi?id=39472). **exec**.

**8. rfc5322_unknown_offset** — format · gpt · [NEW]
- **Mechanism:** `email.utils.parsedate_to_datetime('Wed, 21 Oct 2015 07:28:00 -0000')` returns a **naive** datetime, while `GMT` and `+0000` give aware UTC. Sorting the mix raises `TypeError: can't compare offset-naive and offset-aware`.
- **Determinacy:** "Dates written with -0000 are UTC (the sender's zone is unknown) and sort with the others."
- **Hidden:** three messages with `GMT`, `+0100` and `-0000`. Expected chronological order; wrong is a crash or misorder.
- **Signals:** `parsedate|email\.utils|Date:|mbox|imap`
- **Evidence:** **exec**. I did not open RFC 5322 itself, so cite it from the RFC text when authoring.

### B. Numeric and money

**9. allocation_sum_invariant** — invariant · claude · [NEW]
- **Mechanism:** Rounding each share on its own loses or invents cents. Use the largest-remainder method with a published tie order.
- **Determinacy:** "Split amounts must add back to the original to the cent; leftover cents go to the earliest lines first."
- **Hidden:** 100¢ over 3 gives `[34,33,33]` (wrong `[33,33,33]`, sum 99). 5¢ at 70/30 gives `[4,1]`.
- **Signals:** `split|allocate|prorate|share|percent.*round|per_person`
- **Evidence:** [moneyphp allocation](https://money.readthedocs.io/en/latest/features/allocation.html) (5¢ at [70,30] gives 4/1; $8 into 3 gives 2.67/2.67/2.66). [Betterment penny-precise allocation](https://www.betterment.com/engineering/penny-precise-allocation-functions).

**10. currency_exponent** — numeric · gpt · [NEW]
- **Mechanism:** Code hardcodes `/100` and `.toFixed(2)`. Under ISO 4217, JPY has exponent 0 and KWD/BHD have 3.
- **Determinacy:** "Amounts are stored in the currency's minor unit as ISO 4217 defines it."
- **Hidden:** JPY 1500 minor units should display 1500, not 15.00. KWD 1234 should display 1.234, not 12.34.
- **Signals:** `/ ?100|\* ?100|toFixed\(2\)|cents|minor_unit|currency`
- **Evidence:** [Pliant monetary values](https://customer-api.getpliant.com/docs/monetary-values) (exponent 0 for JPY, 3 for KWD/BHD). [Datatrans currency codes](https://docs.datatrans.ch/docs/currency-codes).

**11. tie_rounding_mode** — numeric idiom · gpt · [SHARPENS numeric idiom betrayal]
- **Mechanism:** Each layer rounds ties differently.
  - Python: `round(2.5)=2`, `round(-2.5)=-2`, `round(2.675,2)=2.67`, `'%.2f'%2.675='2.67'`. `Decimal(2.675)` is 2.67499…; `Decimal('2.675').quantize(Decimal('0.01'))` is 2.68.
  - JS: `Math.round(-2.5)=-2`, `Math.round(2.5)=3`, `(1.005).toFixed(2)='1.00'`.
  - SQLite: `round(-2.5)=-3.0`, `round(0.125,2)=0.13`.
  - Go: `math.Round(-2.5)=-3`.
  - pandas `.round()` is half-even.
- **Determinacy:** "Round half away from zero, like the ledger." Publish the rule, not the cases.
- **Hidden:** 1.005 should be 1.01 and −0.125 should be −0.13. Python float or JS toFixed paths give 1.00 / −0.12.
- **Signals:** `round\(|toFixed|Math\.round|quantize|ROUND_`
- **Evidence:** **exec** in all four runtimes.

**12. floor_vs_truncating_division** — numeric/carry · both · [NEW]
- **Mechanism:** Python floors: `-1//256 = -1`, `-7%2 = 1`. JS, Go and SQLite truncate: `-7/2 → -3`, `-7%2 → -1`. `int(-1/256)` is 0. This bites when code buckets negative coordinates or pre-1970 timestamps.
- **Determinacy:** "Tile 0 covers 0–255 and tile −1 covers −256…−1." Or: "an hourly bucket is the hour the event happened in."
- **Hidden:** x=−1 should be tile −1 (wrong 0). Epoch −1 s should fall in the 1969-12-31T23:00 bucket.
- **Signals:** `Math\.floor|Math\.trunc|\| ?0|int\(.*/|//|%|bucket|tile|grid`
- **Evidence:** **exec**.

**13. nan_poisons_order** — numeric · claude · [NEW]
- **Mechanism:** One NaN breaks ordering. `sorted([3,nan,1,2])` returns `[3,nan,1,2]` unchanged. `max([nan,1,2])` is nan but `max([1,nan,2])` is 2. pandas skips NaN, while builtins and `statistics` do not.
- **Determinacy:** "Runs without a score are left out of the ranking."
- **Hidden:** leaderboard `[3, NaN, 1, 2]`. Expected `[3,2,1]`.
- **Signals:** `float\('nan'\)|NaN|np\.nan|sorted\(|max\(|median`
- **Evidence:** **exec**.

**14. big_integer_ids** — serialization · both · [SHARPENS serialization_contract]
- **Mechanism:**
  - JS: `JSON.parse('{"id":1738234566814937089}').id` becomes …937088 (prints `1738234566814937000`).
  - Go: `json.Unmarshal` into `map[string]any` produces float64 …937088.
  - Python is exact.
  - Fixes: in Node 25 the reviver's third argument `ctx.source` returns the exact digits; in Go use `UseNumber`.
- **Determinacy:** "IDs come back exactly as they were sent."
- **Hidden:** id 2^53+1 and the snowflake above must round-trip byte-exact.
- **Signals:** `JSON\.parse|map\[string\]interface|any\)|snowflake|_id|bigint`
- **Evidence:** [jsonlint W050](https://jsonlint.com/errors/W050) (precision silently lost beyond 2^53). **exec** (Node 25.3, Go 1.23).

### C. Text, Unicode and i18n

**15. line_terminator_superset** — representation · gpt · [NEW]
- **Mechanism:** `str.splitlines()` also breaks on `\x1c \x1d \x1e \x85 \v \f \u2028 \u2029`. `str.split()` with no arguments splits on `\x1c`–`\x1f` (`'a\x1cb c'.split()` gives `['a','b','c']`). JS `split(/\r?\n/)` does not. Ports therefore diverge.
- **Determinacy:** "Records are separated by \n; every other character belongs to the record."
- **Hidden:** a log line `note\x85more` should count as 1 record; `splitlines` gives 2.
- **Signals:** `splitlines\(|\.split\(\)|readlines|line_count`
- **Evidence:** [Yossarian TIL: splitlines does a lot more](https://yossarian.net/til/post/python-s-splitlines-does-a-lot-more-than-just-newlines). **exec**.

**16. crlf_residue** — format · gpt · [SHARPENS format_variant_unseen]
- **Mechanism:** `'abc\r\n'.rstrip('\n')` leaves `'abc\r'`, and Node `'a\r\nb'.split('\n')` gives `['a\r','b']`. Keys then fail equality checks.
- **Determinacy:** "Lines end in \n or \r\n; neither is part of the value."
- **Hidden:** a CRLF config file, where `key=value\r` must equal `value`.
- **Signals:** `rstrip\('\\n'\)|split\('\\n'\)|\.strip\('\\n'\)`
- **Evidence:** **exec**.

**17. strict_digit_class** — adversarial/i18n · gpt · [SHARPENS unicode_semantics]
- **Mechanism:**
  - Python accepts far more than ASCII digits: `int('١٢٣')=123`, `int('１２３')=123`, `int('1_000')=1000`, `int(' 42\n')=42`, and `re.fullmatch(r'\d+','١٢٣')` matches.
  - `'²'.isdigit()` is True but `int('²')` raises `ValueError`.
  - JS `/\d/` is ASCII-only and `Number('1_000')` is NaN.
  - Go `Atoi('1_000')` errors, but `ParseInt(s,0,64)` returns 1000.
- **Determinacy:** "Quantities are written with the digits 0–9 only."
- **Hidden:** `'١٢'`, `'1_000'` and `'²'` must be rejected; `'12'` accepted.
- **Signals:** `int\(|isdigit|isnumeric|\\d|ParseInt\(.*, ?0`
- **Evidence:** [bugs.python.org msg251965](https://bugs.python.org/msg251965) (every decimal character is accepted by int()). **exec**.

**18. anchor_trailing_newline** — adversarial · gpt · [SHARPENS validator_admits_variants]
- **Mechanism:** Python `$` also matches before a final `\n`: `re.match(r'^[a-z]+$','abc\n')` is True. Use `fullmatch` or `\Z` (`\z` in 3.14).
- **Determinacy:** "A duration is a number followed by d, h or m, and nothing else."
- **Hidden:** `"7d\n"` must be rejected.
- **Signals:** `re\.match\(r?['"]\^.*\$|\$['"]\)`
- **Evidence:** [Dify PR #39731](https://github.com/langgenius/dify/pull/39731) (`"7d\n"` slipped through, fixed with fullmatch). [Seth Larson: use \A…\z](https://sethmlarson.dev/use-backslash-A-and-z-not-%5E-and-$-with-python-regular-expressions).

**19. fold_not_lower** — i18n · both · [SHARPENS unicode_semantics]
- **Mechanism:**
  - `'Straße'.lower() != 'STRASSE'.lower()`, but `casefold()` makes them equal.
  - `'admın'.upper()=='ADMIN'` is True while `lower()` and `casefold()` are not equal to `admin`.
  - `'ſ'.upper()=='S'`.
  - Kelvin sign `'\u212a'.lower()=='k'`, and `re.I` matches it unless `re.A` is set.
- **Determinacy:** "Two names are the same if they are equal under Unicode case folding (str.casefold)."
- **Hidden:** `STRASSE` versus existing `straße` should be rejected as a duplicate. `admın` versus `admin` should be distinct. The second case only works because the rule names casefold; see the hazards section.
- **Signals:** `\.lower\(\)|\.upper\(\)|toLowerCase|re\.I|ILIKE|COLLATE NOCASE`
- **Evidence:** [GoSecure on case-mapping security](https://gosecure.ai/?p=2315). **exec**.

**20. canonicalization_idempotence** — identity/security · claude · [NEW]
- **Mechanism:** `'ᴮᴵᴳᴮᴵᴿᴰ'.lower()` leaves it unchanged, but `NFKC(...).casefold()` gives `'bigbird'`. Canonicalising on one path only (signup but not reset or login), or with a non-idempotent function, lets one account take over another.
- **Determinacy:** "Usernames that match after NFKC normalisation and case folding are the same account, at sign-up, login and password reset."
- **Hidden:** existing `bigbird`. Signing up `ᴮᴵᴳᴮᴵᴿᴰ` should fail as taken; resetting `ＢＩＧＢＩＲＤ` should target bigbird. Also require `canon(canon(x)) == canon(x)`.
- **Signals:** `normalize\(|NFKC|canonical|username|slug|unique.*lower`
- **Evidence:** [Spotify Engineering: creative usernames and account hijacking](https://engineering.atspotify.com/2013/6/creative-usernames).

**21. case_map_offset_drift** — i18n · claude · [NEW]
- **Mechanism:** Spans found on `s.lower()` are reused to slice `s`, but lowercasing changes length. `len('İstanbul')=8` while `len('İstanbul'.lower())=9` (i plus U+0307). `'İstanbul İzmir'.lower().find('izmir')` is −1. In JS, `'İ'.toLowerCase().length` is 2 and `'ß'.toUpperCase()` is `'SS'`.
- **Determinacy:** "Highlight positions refer to the original text."
- **Hidden:** find `café` in `İstanbul café`. Expected span (9,13); wrong (10,14).
- **Signals:** `\.lower\(\)\.find|indexOf\(.*toLowerCase|highlight|span|offset`
- **Evidence:** **exec**.

**22. grapheme_safe_truncation** — i18n · gpt · [SHARPENS unicode_semantics]
- **Mechanism:** For `'👨‍👩‍👧'`, JS `.length` is 8 and Python `len` is 5, yet it is 1 grapheme. `'😀abc'.slice(0,1)` returns a lone surrogate `\ud83d`. Use `Intl.Segmenter`.
- **Determinacy:** "Previews count characters as a reader sees them and never cut one in half."
- **Hidden:** truncate `👨‍👩‍👧 trip` to 1 character plus `…`. Expected `👨‍👩‍👧…`.
- **Signals:** `\.slice\(0,|substring\(|\[:\d+\]|truncate|maxLength|ellipsis`
- **Evidence:** [EmojiFYI: grapheme clusters](https://emojifyi.com/stories/grapheme-cluster-counting/). **exec**.

**23. byte_vs_char_length** — protocol · gpt · [NEW]
- **Mechanism:** `len('café')` is 4 but its UTF-8 encoding is 5 bytes (`Buffer.byteLength` is 5). Content-Length or byte limits computed from characters truncate the body, and byte slicing can split a code point.
- **Determinacy:** "The field holds at most 255 bytes of UTF-8."
- **Hidden:** a body of `café` needs Content-Length 5. A 300-byte name cut to 255 must still be valid UTF-8.
- **Signals:** `Content-Length|len\(body\)|\.length.*header|VARCHAR\(255\)|max_bytes`
- **Evidence:** **exec**.

**24. cutset_vs_affix** — idiom · gpt · [NEW]
- **Mechanism:** `strip`, `rstrip`, `lstrip` and Go `TrimRight`/`TrimLeft` take a *character set*, not a suffix or prefix.
  - `'context.txt'.rstrip('.txt')` gives `'conte'`.
  - `'https://shop.example'.lstrip('https://')` gives `'op.example'`.
  - `strings.TrimRight("abc.txt.txt",".txt")` gives `"abc"`.
  - Related: `"they're".title()` gives `"They'Re"`.
- **Determinacy:** "Drop the .txt extension."
- **Hidden:** `context.txt` should become `context`; `https://shop.example` should become `shop.example`.
- **Signals:** `rstrip\(['"]\.|lstrip\(['"]http|TrimRight\(|TrimLeft\(|\.title\(\)`
- **Evidence:** **exec**.

### D. Data and serialization

**25. sentinel_value_collision** — data · both · [NEW]
- **Mechanism:** Loaders turn real values into sentinels or numbers.
  - pandas `read_csv`'s default NA list includes `NA`, `null`, `None` and empty, so Namibia's `NA` becomes NaN. Zip `02134` becomes 2134.
  - PyYAML follows YAML 1.1: `NO`, `no`, `off` become False; `on`, `yes` become True; `version: 1.10` becomes 1.1; `zip: 01234` becomes **668** (octal); `22:22` becomes 1342.
- **Determinacy:** "Country codes (ISO 3166 alpha-2) and ZIP codes come through the import exactly as written."
- **Hidden:** rows `NA,01234`. Expected `'NA'` and `'01234'`.
- **Signals:** `read_csv|yaml\.safe_load|yaml\.load|country|zip|postal`
- **Evidence:** [pandas read_csv docs](https://pandas.pydata.org/pandas-docs/version/2.2/reference/api/pandas.read_csv.html) (default na_values). [The YAML-Norway Law](https://allan.reyes.sh/posts/yaml-norway-law/). **exec**.

**26. null_group_dropped** — data · claude · [NEW]
- **Mechanism:** `df.groupby(col)` defaults to `dropna=True`, silently dropping rows with a NaN key, and `value_counts` does the same. `merge` matches NaN to NaN, unlike SQL. SQL `GROUP BY` keeps a NULL group.
- **Determinacy:** "Every order counts toward exactly one region; orders with no region are reported as 'Unassigned'."
- **Hidden:** two rows with no region. Expected an `Unassigned` total, with all totals summing to the grand total. Wrong: the group is missing.
- **Signals:** `groupby\(|value_counts|pivot_table|nunique`
- **Evidence:** [pandas groupby docs (1.3)](https://pandas.pydata.org/pandas-docs/version/1.3/reference/api/pandas.DataFrame.groupby.html) (dropna=True drops NA keys). **exec** (pandas 3.0.6).

**27. null_in_anti_join** — data · gpt · [SHARPENS adversarial_rule_inputs]
- **Mechanism:** `x NOT IN (subquery containing a NULL)` returns **0 rows**; `NOT EXISTS` returned 3. Related: `COUNT(col)` skips NULLs, `SUM` over no rows is NULL (`total()` is 0.0), and `'x'||NULL` is NULL.
- **Determinacy:** "List customers with no orders; orders that have no customer don't affect the list."
- **Hidden:** a single order row with NULL `customer_id`.
- **Signals:** `NOT IN \(SELECT|SUM\(|COUNT\(\w+\)|LEFT JOIN`
- **Evidence:** [jOOQ: don't use NOT IN](https://www.jooq.org/doc/3.9/manual/reference/dont-do-this/dont-do-this-sql-not-in/). **exec** (SQLite).

**28. like_wildcard_literal** — adversarial/data · gpt · [NEW]
- **Mechanism:** User text goes straight into `LIKE '%'||?||'%'`, where `_` and `%` are wildcards (`'axb' LIKE 'a_b'` is 1). SQLite's LIKE is case-insensitive for ASCII only, while `=` is case-sensitive.
- **Determinacy:** "Search finds the typed text literally anywhere in the title."
- **Hidden:** query `50%_off` must not match `500 off` or `50%Xoff`; it must match `save 50%_off`.

**29. csv_structural_long_tail** — data · claude · [SHARPENS format_variant_unseen]

**30. formula_injection_full_set** — adversarial · gpt · [NEW]

**31. duplicate_and_case_key_smuggling** — protocol/adversarial · both · [NEW]
- **Mechanism:** Python `json`, PyYAML and Go keep the *last* duplicate key. Go `encoding/json` v1 also matches field names case-insensitively: `{"NAME":"x","Name":"y","name":"z"}` decodes Name as `z`.

**32. json_pointer_unescape_order** — protocol · gpt · [NEW]
- **Mechanism:** RFC 6901 decodes `~1` to `/` *first*, then `~0` to `~`. Reversing the order turns `a~01b` into `a/b` instead of `a~1b`. Encoding uses the inverse order.

**33. merge_patch_semantics** — protocol/state · claude · [NEW]
- **Mechanism:** `{**a, **b}` and `a | b` are shallow: `{'a':{'x':1}} | {'a':{'y':2}}` gives `{'a':{'y':2}}`. Under RFC 7396, null *deletes* a member, arrays are replaced whole, and objects recurse.

### E. HTTP and protocol

**34. form_vs_percent_plus** — protocol · gpt · [SHARPENS format_variant_unseen]
- **Mechanism:** `URLSearchParams` and `parse_qs` decode `+` as a space; `decodeURIComponent` and `unquote` do not. `new URLSearchParams({q:'a b+c'})` serialises as `q=a+b%2Bc`. A raw `+` in a token becomes a space.
- **Determinacy:** "The token reaches the server exactly as issued."
- **Hidden:** token `ab+c/d==` passed in a query string must round-trip.
- **Signals:** `URLSearchParams|decodeURIComponent|parse_qs|unquote\(|querystring`
- **Evidence:** [MDN URLSearchParams](https://developer.mozilla.org/en-US/docs/Web/API/URLSearchParams) (+ is read as a space). [Eclipse bug 571831](https://eclipse.googlesource.com/platform/eclipse.platform.ua/+/refs/tags/I20210423-0350%5E%21/). **exec**.

**35. conditional_request_comparison** — protocol · both · [NEW]
- **Mechanism:** RFC 9110 uses **weak** comparison for If-None-Match (`W/"v1"` matches `"v1"`) and **strong** comparison for If-Match (a W/ tag never matches). Both take lists and `*`. On a GET, an If-None-Match match returns 304; for other methods it returns 412.
- **Determinacy:** "Conditional requests behave as RFC 9110 specifies."
- **Hidden:** current ETag `"v1"`.
  - GET with `If-None-Match: "v9", W/"v1"` should return 304.
  - PUT with `If-Match: W/"v1"` should return 412.
  - PUT with `If-None-Match: *` on an existing resource should return 412.
- **Signals:** `ETag|If-None-Match|If-Match|304|412`
- **Evidence:** [RFC 9110 §13.1.1–13.1.2](https://www.rfc-editor.org/rfc/rfc9110.txt) ("MUST use the weak comparison function … If-None-Match"; "MUST use the strong comparison function … If-Match").

**36. byte_range_long_tail** — protocol · claude · [NEW]
- **Mechanism:** Agents implement `bytes=a-b` only. RFC 9110 also has suffix ranges (`bytes=-N`, where N larger than the length means the whole representation), open ranges (`a-`), last-pos clamping, and 416 with `Content-Range: bytes */len`.
- **Determinacy:** "Answer every satisfiable Range request with 206, as RFC 9110 defines ranges." Say 206 explicitly, because the RFC lets servers ignore Range.
- **Hidden:** a 300-byte file.
  - `bytes=-500` should return 0-299/300.
  - `bytes=100-999` should return 100-299.
  - `bytes=400-` should return 416 with `bytes */300`.
- **Signals:** `Range|Content-Range|206|416|seek|stream`
- **Evidence:** [RFC 9110 §14.1.2](https://www.rfc-editor.org/rfc/rfc9110.txt) (if the representation is shorter than the suffix length, the entire representation is used; `Content-Range: bytes */1234`).

**37. qvalue_zero_exclusion** — protocol · gpt · [NEW]
- **Mechanism:** A substring test like `'text/html' in accept` ignores weights. `q=0` means *not acceptable*.
- **Determinacy:** "Respect the client's Accept header as RFC 9110 defines it."

- **Evidence:** [RFC 9110 §12.4.2](https://www.rfc-editor.org/rfc/rfc9110.txt) ('a value of 0 means "not acceptable"').

**38. set_cookie_unfoldable** — protocol · claude · [NEW]
- **Mechanism:** Proxy or middleware code stores headers in a dict joined with `", "`. `Expires=Wed, 21 Oct…` contains a comma, so `split(',')` produces fragments.

**39. forwarded_chain_trust** — adversarial/protocol · gpt · [NEW]
- **Mechanism:** Code takes the leftmost `X-Forwarded-For` entry, which the client controls. With N trusted proxies, take the first untrusted address from the right.
- **Determinacy:** "We sit behind exactly one load balancer that appends the address it saw; clients must not be able to pick their own address."

**40. address_notation_differential** — adversarial · gpt · [NEW]

**41. scheme_check_normalization** — adversarial · gpt · [SHARPENS adversarial_rule_inputs]

**42. raw_body_signature** — protocol/security · claude · [NEW]
- **Mechanism:** Code computes the HMAC over re-serialised JSON. Python turns `\u00e9` into `é` with `ensure_ascii=False`, and key order and spacing differ. Agents also take the first `v1=` only, skip the timestamp tolerance, or compare lengths unsafely.

**43. idempotency_key_contract** — state/protocol · both · [SHARPENS persistent_state_across_runs]
- **Mechanism:** The contract has three parts: the same key with the same params replays the saved status and body with no new side effect; the same key with different params is an error; validation failures are not saved.

**44. keyset_tiebreak** — state/data · claude · [NEW]

**46. semver_precedence** — ordering · gpt · [SHARPENS ordering idiom]
- **Mechanism:** String sort puts `beta.11 < beta.2`. Under SemVer, numeric identifiers compare numerically and rank below alphanumeric ones, a prerelease ranks below its release, and build metadata is ignored.
- **Determinacy:** "Versions follow SemVer 2.0.0."
- **Hidden:**

  - `1.0.0-rc.1 < 1.0.0`;

- **Evidence:** [semver.org](https://semver.org/). [Octopus on SemVer 2](https://octopus.com/blog/semver2) (alpha10 sorted before alpha2 under lexical order). Python PEP 440 differs again (`1.0.0.dev1 < a2 < a10 < rc1 < 1.0.0 < .post1`; `Version('1.0')==Version('1.0.0')`) per **exec**.

**47. cron_day_fields_or** — interaction · both · [NEW]

- **Determinacy:** "Schedules use standard crontab(5) syntax and meaning."

**48. ignore_pattern_semantics** — scope · claude · [NEW]
- **Mechanism:** Under gitignore rules:

  - a leading or middle `/` anchors the pattern;

  Python `fnmatch('a/b/c.py','*.py')` is True, so it does cross `/`.

**49. empty_or_relative_env** — environment · both · [SHARPENS ecosystem_env_convention]

**50. shell_status_and_containment** — environment/adversarial · gpt · [NEW, plus SHARPENS adversarial_rule_inputs]

| 10 | `Range: bytes=-500` on a 300-byte file with `If-None-Match: W/"v1"` and current ETag `"v1"` | byte_range_long_tail (suffix branch) | conditional_request_comparison (weak compare, 304 takes precedence) |

To prove each lever, use an `m_partial_` mutant that fixes only one side of the cell. The `m_baseline_` mutant is the "obvious" implementation in that row.

## 3. Validity hazards (look hard, but are ambiguous or unfair unless the instruction settles them)

- **Turkish dotted and dotless i.** Default case folding is locale-free. `'İ'.casefold()` gives `'i̇'`, so `'İzmir'` does not contain `'izmir'` under any default fold. Do not test Turkish semantics unless a locale is named.
- **"Round to the nearest cent"** without a tie rule. Half-even and half-up are both defensible, so name the rule.
- **CSV-injection `-` prefix.** Prefixing negative numbers changes legitimate data. The instruction must say whether `-5` is escaped.
- **NO_PROXY matching** (leading dot, CIDR, ports). There is no standard and curl, Python, Go and wget disagree ([GitLab: can we standardize NO_PROXY?](https://about.gitlab.com/blog/we-need-to-talk-no-proxy/)). Only test a rule the instruction spells out.
- **YAML 1.1 vs 1.2** (PyYAML follows 1.1; other parsers follow 1.2). `no`, `010` and `1.10` differ by parser, so pin the parser or state the expected value class.
- **Excel serial 60** (phantom 1900-02-29) and the 1904 date system. Exclude them or rule on them explicitly.
- **DST gap times** (for example 02:30 on 2024-03-10 in New York). The resolution is arbitrary (PEP 495 / datetime-sig), so publish it or avoid the case.
- **Version-dependent stdlib and library behaviour.** Pin the image and avoid these unless the toolchain is fixed:
  - `ipaddress` IPv4-mapped properties changed around 3.13; `fromisoformat('…Z')` needs 3.11+; `\z` needs 3.14.
  - packaging's `SpecifierSet` prerelease handling: in packaging 26.3 `Version('2.0.0rc1') in SpecifierSet('>=1.0')` returned True, which older releases did not.
  - pandas' default NA list has changed (`None` added in 2.x).
  - IDNA 2003 and 2008 treat `ß` differently.
- **Locale-dependent output** (`toLocaleString()` with no locale, `%x`, `locale.str`). It depends on the host's `LANG`, so either set it in the test or avoid it.
- **Inconsistent JS comparators** (`(a,b)=>a>b`). The sort order is implementation-defined. It is deterministic for a pinned V8, but an expert can argue about it.
- **Async races judged by wall-clock timers.** Use microtask-only or fake-timer fakes. Never grade on interleavings that real timing decides.
- **Filesystem case-insensitivity and NFD filenames.** Docker Linux and macOS hosts differ, so it is not reproducible in the verifier.
- **Ignoring Range or ETag.** RFC 9110 lets servers ignore Range and send 200. Require 206 explicitly.
- **SemVer ties on build metadata.** `max(["1.0.0","1.0.0+b5"])` has no unique answer. Test comparisons, not argmax.
- **"Case-insensitive"** without naming lower, upper or casefold, and **"valid email"** without naming a grammar. Both are underdetermined, so name the rule.
